# 🌸 Как пользоваться программой «Поиск кадров по DI и GI»   (Текст сгенерирован нейросетью с промптом "для блондинки" :D )

Этот README объясняет **на пальцах**, как запустить скрипт
`select_frames_by_DI_GI.py`, чтобы из длинной молекулярно-динамической
траектории выудить те самые кадры, где система выглядит так, как вам нужно.

---

## О чём вообще эта программа? (версия для нетерпеливых)

Представьте: у вас есть **видео** длиной в миллион кадров, на котором шесть
молекул каликсарена («чашечек») плавают в коробке и всячески поворачиваются
друг к другу. Смотреть этот миллион кадров глазами — как искать иголку в
стогу сене. 😵

Программа делает две вещи:

1. **Считает для каждого кадра два числа** — как бы «оценки» формы cluster'а:
   * **DI (Dimer Index)** — насколько чашечки смотрят друг на друга
     «дно в дно» (диммеры/стопки). Грубо: *парность и параллельность*.
   * **GI (Growth Index)** — насколько чашечки развернуты «борта в борта»,
     то есть растут в широкий шар/кольцо. Грубо: *раскрытие кластера*.

2. **Отбирает кадры**, где эти две оценки близки к тем числам, которые вы
   задали (например, вы посмотрели карту свободной энергии и сказали:
   «хочую стартовать simulations вот от этой точки»).

Всё! На выходе — маленькая траектория только из нужных кадров + табличка со
всеми значениями.

## Шаг 0. Что должно быть установлено

Нужен Python 3.8+ и три библиотечки:

```bash
pip install numpy MDAnalysis matplotlib
```

* `numpy` и `MDAnalysis` — обязательны;
* `matplotlib` — только если хотите картинку-гистограмму (флаг `--plot`).

Проверить, что всё ок:

```bash
python -c "import MDAnalysis; print(MDAnalysis.__version__)"
```

## Шаг 1. Какие файлы нужны на входе (это важно!)

| Файл | Что это такое простыми словами | Пример |
|---|---|---|
| **Топология** `.gro` (или `.pdb`) | «Свидетельство о рождении» системы: кто есть кто, порядок атомов, размеры коробки. Берётся обычно из начала вашего прогона (`conf.gro`, `topol.tpr`, `ref_nosolv.gro`). | `ref_nosolv.gro` |
| **Траектория** `.xtc` | Само «видео» — координаты всех атомов по кадрам. | `traj.xtc` |
| **Index-файл про кислороды** `.ndx` | Текстовый список: атомы №… — это «центральные кислороды» чашечки 1, атомы №… — чашечки 2 и т.д. Имена групп **обязательно** должны быть: `cal1_centralO`, `cal2_centralO`, …, `cal6_centralO`. | `index_singoli_O.ndx` |
| **Index-файл про хвосты** `.ndx` | То же самое, но для «хвостовых углеродов»: `cal1_tailC`, …, `cal6_tailC`. | `index_singoli_C.ndx` |

⚠️ Нумерация атомов внутри `.ndx` — **с единицы** (как принято в GROMACS),
скрипт сам всё правильно пересчитает. Не надо ничего править руками.

Примеры таких файлов лежат здесь: <https://github.com/elinaquant/test.git>.

Если у вас нет готовых index-групп — их легко сделать командой:

```bash
gmx make_ndx -f ref_nosolv.gro -o index_singoli_O.ndx
```

и там вручную создать группы (по номерам атомов из топологии).

## Шаг 2. Самая простая команда запуска (скопируй и работай 💅)

```bash
python3 select_frames_by_DI_GI.py \
    --gro      ref_nosolv.gro \
    --xtc      traj.xtc \
    --ndx_O    index_singoli_O.ndx \
    --ndx_C    index_singoli_C.ndx \
    --DI       -0.5 \
    --GI        0.3 \
    --out_xtc  selected.xtc \
    --out_csv  all_frames.csv
```

Что здесь происходит, по строчкам:

* `--gro` / `--xtc` / `--ndx_O` / `--ndx_C` — четыре входных файла из Шага 1;
* `--DI -0.5` и `--GI 0.3` — **целевая точка** на карте свободной энергии,
  ту цифирки вы обычно берёте прямо с графика FES (минимум, где хотите
  стартовать);
* `--out_xtc selected.xtc` — сюда program запишет отобранные кадры
  (коротенькая траектория — то, что потом можно отдать в `gmx energy`,
  визуализацию или новый прогон). Вместе с ним автоматически создаётся
  `selected.gro` — референсная топология ровно на те же атомы и в том же
  порядке. **ВАЖНО:** XTC хранит только координаты, без имён атомов; если
  открыть его в ChimeraX/VMD вместе с solv-топологией (14451 ат.), будет
  ошибка «Specified structure has N atoms whereas the coordinates are for
  456 atoms». Открывайте пару: `open selected.gro`, затем
  `movie read selected.xtc start <первый_кадр>`;
* `--out_csv all_frames.csv` — сюда запишется **таблица всех кадров**:
  `frame, time_ps, DI, GI`. Откройте её в Excel и посмотрите, как живут
  ваши переменные. Это полезно, чтобы понять, куда вообще ставить цель!

Готово. В конце скрипт напечатает короткий отчёт: сколько всего кадров
просмотрено, сколько попало в окно, какие номера отобраны, минимальные и
максимальные DI/GI по траектории.

## Шаг 3. Допуск: «близко» — это насколько близко?

Кадр считается подходящим, если одновременно:

```
|DI_кадра − DI_цели| ≤ tol_DI        (по умолчанию 0.2)
|GI_кадра − GI_цели| ≤ tol_GI        (по умолчанию 0.3)
```

То есть мы рисуем вокруг целевой точки **прямоугольничек** и собираем все
кадры внутрь него. Регулировать размер прямоугольничка можно флагами:

```bash
    --tol_DI 0.1 --tol_GI 0.15
```

* маленький допуск → мало кадров, но они очень точно в точке;
* большой допуск → много кадров, но разбросанных.

Совет: сначала прогоните без претензий, откройте CSV (или картинку из Шага 4),
посмотрите, где реально живут значения — и уже потом выбирайте цель и допуск.

## Шаг 4. Хочу картинку! (флаг `--plot`)

Добавьте в команду два флага:

```bash
    --plot --out_png fes_hist.png
```

Скрипт построит **тепловую карту** (2D-гистограмму) распределения кадров по
(DI, GI), отметит красным крестиком вашу целевую точку и пунктиром — границы
допуска. Очень наглядно: видно, попали ли вы вообще в «обитаемую» область.

**Перерисовать карту без пересчёта траектории** можно по уже готовому CSV
(колонки `frame,time_ps,DI,GI`) — режим `--from_csv` читает таблицу за
миллисекунды, MDAnalysis/траектория не загружаются:

```bash
python3 select_frames_by_DI_GI.py --from_csv all_frames.csv \
    --DI 0.7 --GI 11.0 --tol_DI 0.2 --tol_GI 0.3 --out_png fes_hist.png
```

Здесь `--DI/--GI` задают только положение звёздочки и рамки допуска на графике
(не заданы — поставит в медиану); отобранный XTC/CSV в этом режиме не
трогаются. Флаг `--plot` с `--from_csv` не нужен — карта строится всегда.

## Шаг 5. Кадров в окне нет / нужно ровно N штук

Бывает два неприятных случая и одно удобное желание:

1. **В прямоугольничек не попал ни один кадр.** Скрипт сам предупредит об
   этом и подскажет ближайший кадр к цели (его номер и расстояние). Это
   значит: либо увеличьте допуск, либо подвиньте цель.
2. **Хочу не «все, что в окне», а ровно, скажем, 10 самых близких кадров.**
   Тогда вместо окна используйте флаг:

   ```bash
       --top_n 10
   ```

   Программа отсортирует все кадры по евклидову расстоянию от точки (DI, GI)
   и возьмёт 10 лучших, независимо от допуска.

|---|---|---|---|
| `--gro` | ✅ да | — | топология (.gro/.pdb) |
| `--xtc` | ✅ да | — | траектория (.xtc) |

## Шаг 7. Что делать, если ругается? (частые болячки 🩺)

| Сообщение | Что значит | Что делать |
|---|---|---|
| `Index-файл не найден: ...` | Опечатка в пути к `.ndx` | Проверьте, что файл лежит рядом и имя совпадает буква в букву |
| `В index-файле '...' отсутствует группа 'cal3_centralO'` | В `.ndx` нет группы с таким именем или оно написано иначе | Убедитесь, что имена групп ровно `cal1_centralO`…`cal6_centralO` и `cal1_tailC`…`cal6_tailC` (регистр важен!). Скрипт сам подскажет, какие группы он видит в файле |
| `Группа 'cal2_tailC' ... содержит индексы вне диапазона 1..N` | Index-файл от другой системы / другая нумерация | Пересоздайте `.ndx` из той же топологии, что подаёте в `--gro` |
| `ПРЕДУПРЕЖДЕНИЕ: в топологии N атомов вместо ожидаемых 456` | В системе не 6×76 атомов — возможно, это не та модель | Проверьте, правильный ли `.gro` подан; для других размеров систему скрипт считать не будет |
| `Ни один кадр не попал в окно допуска` | Цель стоит в пустой области карты | Смотрите картинку `--plot`, двигайте цель или увеличивайте `--tol_*` |
| `No module named MDAnalysis` | Библиотека не установлена | `pip install MDAnalysis` |

## Если DI и GI везде получаются ~0.000 (или меняются только на тысячные доли)

Это классическая ловушка с единицами в весовом множителе `1/(1 + d^12)`:

* В эталонной постановке PLUMED/GROMACS расстояние `d` в этой формуле
  подставляется **в нанометрах** (при d = 1 нм вес равен ровно 1/2).
* Единицы входных файлов при этом **не гарантированы**: данная траектория
  `superlight_traj.xtc` (и `ref_nosolv.gro`) записана **в ангстремах** —
  бокс ~598×964×708 при мономере размером ~4 нм. MDAnalysis отдаёт эти
  числа «как есть», и если подставить их в формулу напрямую, то
  `d^12 ~ 1e15…1e18`, вес схлопнется в ~0, и на всех кадрах получатся
  DI ≈ 0.004 и GI ≈ 0.0002 вместо величин порядка единиц. Именно эта
  ошибка (смешение ангстремных координат с нанометровой формулой веса)
  была причиной «нулевых» значений в ранней версии скрипта.
* **Исправление:** скрипт автоматически определяет единицы по физическому
  размеру мономера (первый кадр) и, если координаты пришли в ангстремах,
  переводит координаты и бокс каждого кадра в нанометры перед вычислом
  центров, осей и `d_ij`. В stdout печатается сообщение какого типа
  единицы обнаружены. Для `superlight_traj.xtc` теперь получается
  DI ∈ (−1.4, +3.0), GI ∈ (0, +11.6) — ожидаемый масштаб.
* Ожидаемый масштаб значений: DI ∈ (−15, +15), GI ∈ [0, +15] — суммы по
  15 парам с весами от 0 до 1 (вес близок к 1 только для очень близких пар
  d < 1 нм; при d ≈ 1 нм вес = 0.5; при d ≥ 2 нм вес уже < 0.001).
  Целевые точки (`--DI`, `--GI`) задавайте по таблице `--out_csv` или по
  картинке `--plot`, а не «на глаз» из легенды FES в других единицах.

## Мини-FAQ

**— Почему DI/GI у меня чуть-чуть не совпадают со значениями из PLUMED?**
Скрипт повторяет формулы PLUMED (WHOLEMOLECULES + геометрический CENTER +
minimum image), поэтому совпадение точное в пределах численной погрешности.
Если расхождение большое — проверьте, что `.gro` и `.xtc` из одного прогона и
что индексы в `.ndx` правильные.

**— Можно ли смотреть траекторию в VMD/Chimera?**
Да, `selected.xtc` — обычная XTC. Для визуализации подгрузите к ней тот же
`.gro`: `vmd ref_nosolv.gro selected.xtc`.

**— Долго ли считает?**
Порядка секунды на кадр для системы из 456 атомов. Миллион кадров = пара
часов, зато прогресс печатается каждые 1000 кадров (`--progress` можно
уменьшить или увеличить).

**— Это платно?**
Бесплатно и с открытым кодом. Пользуйтесь на здоровье! 💖

## Совсем коротко (TL;DR)

```bash
pip install numpy MDAnalysis matplotlib

python3 select_frames_by_DI_GI.py \
    --gro ref.gro --xtc traj.xtc \
    --ndx_O O.ndx --ndx_C C.ndx \
    --DI -0.5 --GI 0.3 \
    --out_xtc sel.xtc --out_csv all.csv \
    --plot --out_png hist.png
```

Всё, вуаля: в `sel.xtc` — нужные кадры, в `all.csv` — таблица, в `hist.png` —
красивая картинка. ✨
